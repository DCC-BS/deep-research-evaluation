Scoring method

MUST requirements are gates. An option that fails one and cannot close it cheaply drops out. SHOULD and COULD requirements score 0 to 3, and the category scores are combined with these weights, set from the interview priorities.

Are pipes still supported?

Yes. Pipe functions are a first-class extension point in v0.11.4 and in current main (functions.py registers every active pipe as a model; 0.11 added enable/disable events and multi-select valves for functions). The only switch is ENABLE_PLUGINS, which is on by default and not set in our values. The separate "Pipelines" server is a different product, disabled in our chart, and not needed: the pipe calls our job service directly.

NVIDIA Deep Researcher chart check

Rendered with helm template (chart 2.2.0, web profile): 3 Deployments (backend, frontend, postgres), 1 PVC, an nginx Ingress, no emptyDir. What our cluster needs:

  • Restricted PSS: the containers drop all capabilities and block privilege escalation, but the pod securityContext is null, so runAsNonRoot and the seccomp profile are missing. The chart accepts podSecurityContext per app, so a values override fixes it. Images already run as UID 1000.
  • Postgres: the bundled bitnami/postgresql:latest and its init container (no securityContext) should be replaced by our managed Postgres, as for OWUI. The init SQL runs once.
  • Emptydir cap: no emptyDir volumes. Chroma and relay logs write into the container filesystem, which is fine at the 4Gi limit, or we turn them off.
  • Network: swap the nginx Ingress for an HTTPRoute, or skip it entirely since OWUI is the frontend. Add HTTP(S)_PROXY and NO_PROXY via env.
  • NGC: images are on nvcr.io, so we need an NGC API key as pull secret, which you have. NVIDIA_API_KEY is only for NVIDIA-hosted models and is not needed with our vLLM. The code is Apache-2.0, and an AI Enterprise licence is probably not required.
  • OpenShell is optional. Only the experimental config_openshell and the data-science profiles use a sandbox (OpenShell or Modal, one per job). The default web config runs without one, and charts fall back to Markdown tables or inline chart specs. If Agent Sandboxes become available, sandboxed analysis skills can be added later.
  • Jobs: by default jobs run on Dask inside the backend pod, so a restart kills running jobs. An example config adds a shared Dask scheduler and worker pool (TLS), which keeps jobs alive across API restarts and lets the worker count scale up at night.

Recommendation

Shortlist GPT-Researcher (through a fork of the OWUI bridge), the NVIDIA Deep Researcher Agent, and an own build as the fallback. Benchmark both external engines with Gemma-4-31B against two baselines: the seeded OWUI model and Gemma without search. Citation accuracy is the expected weak point for ~30B models, so weight FACT heavily. If both engines miss the citation gate, build our own around citations that keep their source quote, or pilot MiroThinker-1.7-mini as the search sub-agent. Don't host a research-specialised model before then.

Architecture shared by every shortlisted option

Thin OWUI pipe ("Deep Research" model, access limited to Entra groups) → research job service with run state in Postgres and one K8s Job per run, so runs survive pod restarts and the 30-minute HTTP timeout. The pipe submits a job and polls it, streaming status and citations. Clarifying questions and plan approval run as chat turns before submission. A quota filter backed by Redis enforces per-user budgets. n8n sends notifications and offers the API entry point. Deep runs go into a queue that only drains in the night window (20:00–05:00 CET, set via GitOps), so office-hour GPU load stays unchanged. The finished report is posted back into the originating chat. A model gateway (LiteLLM) in front of vLLM counts tokens per run and exposes role aliases, e.g. gemma-think and gemma-fast with different chat_template_kwargs, so any framework gets per-role thinking without code changes.

Protocol deviations

  • 20 of 50 English DRB tasks, chosen for closeness to administrative work, in two stages to keep judge costs low.
  • FACT scrapes cited pages with our Firecrawl instead of the Jina Reader. Pages it can't fetch (paywalls, Reuters, some PDFs) count as "unknown", and DRB leaves those out of the accuracy calculation.
  • A FACT focus step cuts each page to the 16k characters most relevant to the cited claims (local embeddings). A plain prefix cap marked long PDFs "unsupported": 31.6% vs 38.1% on the same report.

Fixes during setup

  • At 82% GPU memory, vLLM ran out of memory on long prompts once the embedding server was up. Gemma now runs at 80%, embeddings at 10%.
  • NVIDIA ships only Tavily as web search. The gateway now offers a Tavily-compatible endpoint backed by Serper and Firecrawl, so no plugin was needed.
